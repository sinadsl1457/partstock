# AI 작업 기록

AI가 틀렸거나 방향을 바꾼 지점. 경과 시간 / 한 일 / 틀린 것 → 고친 것.

- 0:00 Spring Initializr로 뼈대 생성: 의존성 이름을 `webmvc`로 넣어 400 에러 → Initializr 목록에서 `web`이 webmvc 스타터임을 확인하고 고침
- 1:20 eBay 검색 호출 작성: 검색 조건 `buyingOptions:{FIXED_PRICE}`를 주소에 그대로 넣어 Spring이 중괄호를 주소 변수로 해석 → 가짜 서버 테스트에서 "Not enough variable values" 에러로 발견, 조건을 변수로 넘기게 고침
- (11/21) 실제 eBay 응답으로 점검: 램 구성 규칙을 "2x16GB"만 받게 만들어 "(2x16)"·"(2x16G)" 정상 글을 버리고 있었음 → 실제 제목을 테스트에 넣고 GB 없는 형태도 받게 고침. 같은 판매자가 같은 글을 여러 개 올려 중앙값이 부풀던 것도 실제 데이터에서 발견 → 같은 제목·가격은 한 번만 셈
- (11/21) 중복 제거 테스트의 기댓값을 이상값 제거를 빼먹고 계산(101,500 → 실제 101,000). 코드가 아니라 테스트를 고침
- (11/22) 시세 API: 제조사·모델 목록에 다나와 상품 번호를 넘기지 않아 항상 검색 링크가 나감, 수집 전 빈 DB에서 `max(day)`가 null이라 500 에러 → API 테스트에서 둘 다 발견해 고침
- (11/22) 웹: Next.js 16 규칙을 놓침 — 서버 컴포넌트에서 클라이언트 차트로 함수(안내 문구 함수)를 넘김, 주소(params)·usePathname을 Suspense 밖에서 읽음 → 개발 서버 로그와 브라우저 콘솔 에러로 발견해 고침. 램 "데스크톱" 글자를 서버가 한국어로 줘서 영어 화면에 한국어가 나옴 → 코드(DESKTOP)로 바꿈
- (11/22) 사용자 피드백 "주식·코인처럼 누르면 그래프가 안 나온다": 하루 한 번 수집 + 표 중심 화면이라 차트가 일주일 넘게 비는 구조였음 → 매시간 수집, 코인 거래소 배치(목록 + 큰 차트)로 다시 만듦. 처음 설계 때 "데이터가 쌓이기 전 화면이 어떻게 보이나"를 확인하지 않은 것이 원인
- (11/22) 차트 아래 "언제부터 수집"을 주봉 첫 봉 시작(월요일)으로 계산해 11/16로 잘못 나옴 → 서버가 실제 첫 수집 시각을 주게 고침
